Call stack: cada chamada de função ganha um frame

código

Observação: pilha e heap são regiões da mesma memória. A pilha guarda valores e endereços (setas); o objeto, inclusive a função, fica no heap.

  1. 1. principal() é chamada: um frame entra na pilha.
  2. 2. A variável local x mora no frame de principal.
  3. 3. dobro(x) empilha outro frame por cima, com seus próprios n e resultado.
  4. 4. return: o frame de dobro é descartado e o valor volta para y.
  5. 5. principal termina e o frame some. Variável local morre com a função.

Observação: primitivo guarda o valor na pilha; objeto guarda só o endereço (seta) e vive no heap. Um objeto pode apontar para outro: a propriedade tags guarda o endereço do array.

  1. 1. Primitivo: a variável guarda o próprio valor.
  2. 2. copia = idade copia o valor. Mudar copia para 21 não mexe em idade: continua 20.
  3. 3. Objeto vive no heap; a variável guarda só o endereço. E a propriedade tags também: guarda o endereço do array, que é outro objeto no heap.
  4. 4. b = a copia o endereço: um objeto, duas variáveis apontando.
  5. 5. Alterar por b altera o mesmo objeto, e o mesmo array: a enxerga tudo. O React compara endereços.

Anatomia de um componente

TaskItem.tsx · clique numa parte

type TaskItemProps = {
    task: Task
    onToggle: (task: Task) => void
}function TaskItem({ task, onToggle }: TaskItemProps) {    const decoration = task.is_done ? "line-through" : "none"    return (
        <li onClick={() => onToggle(task)}
            style={{ textDecoration: decoration }}>
            {task.name}
        </li>
    )}<TaskItem task={task} onToggle={toggle} />

Parâmetros. O componente recebe um único objeto, o props, desestruturado na assinatura e tipado com TaskItemProps. É somente leitura: o filho lê, o dono é o pai.

Código. TypeScript comum, antes do return. Roda inteiro a cada renderização: aqui calcula decoration a partir de task.is_done.

Retorno. É o que renderiza: o JSX devolvido vira a tela. Cada renderização produz um JSX novo para os parâmetros e o estado atuais. { } abre uma expressão; um único elemento raiz.

Uso. Uma tag com o nome da função, sempre maiúsculo. Os parâmetros viram atributos; função e variável vão entre chaves.

O pai injeta a função, a filha executa

pai · TaskApp (dono do estado)

function toggle(task: Task) {    setTasks(/* marca a task */)} return (  <TaskItem task={task}    onToggle={toggle} />)

filha · TaskItem (só executa)

function TaskItem({ task, onToggle }) {  return (    <li onClick={() =>      onToggle(task)}>      {task.name}    </li>  )}
  1. 1. O pai escreve a função toggle: só ele conhece o estado e sabe como alterá-lo.
  2. 2. O pai injeta a função como parâmetro: onToggle={toggle}. Passa a referência (o endereço da função no heap), sem executar.
  3. 3. A filha só recebe um onToggle e liga no clique. Ela não sabe o que a função faz.
  4. 4. No clique, a filha executa onToggle(task), e roda o código do pai: setTasks, nova renderização.
IoC

Inversão de controle: quem decide o que acontece é o pai; a filha decide só quando chamar. É a mesma ideia do addEventListener e dos middlewares do Express.

Estado: de Alan Turing ao semáforo

estado atualpassa o tempo →
"verde""amarelo"
"amarelo""vermelho"
"vermelho""verde"
estado =
  • Máquina de Turing (1936): fita, cabeçote, tabela de transição e um estado atual
  • Estado = tudo que o sistema precisa lembrar do passado para decidir o que fazer agora. Mesmo evento, resultado depende do estado
  • Em orientação a objetos, o estado são os valores atuais das propriedades do objeto instanciado de uma classe: new Task("Estudar") começa com isDone = false, e complete() muda o estado
git

Essa foto é o famoso snapshot, como um commit do Git: guarda o projeto inteiro naquele momento, e o evento leva de um snapshot ao próximo.

Gerenciar estado = responder: quem é o dono, quem lê, quem muda e quem precisa ser avisado.
